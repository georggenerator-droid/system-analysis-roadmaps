# J11 Разберись в форматах сообщений

[← Маршрут](../README.md) · [Назад: J10](j10-sql-joins.md) · [Дальше: J12 →](j12-rest-api.md)

**Результат:** ты читаешь JSON и XML, описываешь ограничения данных и не путаешь пример со схемой. Ориентир — 14 часов.

В JSON изучи объект, массив, строку, число, boolean и null. Отличай отсутствующее поле от поля со значением null, а пустой массив — от отсутствия коллекции. Одинаковое на вид значение может иметь разный тип: `"100"` не равно числу `100` в контракте.

Для каждого поля фиксируй тип, обязательность, допустимые значения, формат и смысл. JSON Schema описывает проверяемую структуру сообщения. Пример показывает один допустимый экземпляр; по нему нельзя понять все ограничения. Для XML нужны элементы, атрибуты, namespace и базовое представление о XSD. Подробную разработку SOAP-сервисов пока оставь на специализацию.

**Обязательно:**

- [S19 JSON](https://developer.mozilla.org/ru/docs/Web/JavaScript/Reference/Global_Objects/JSON) · RU. Изучи типы и ограничения формата JSON. Обрати внимание на кавычки, отсутствие комментариев и завершающих запятых.
- [S37 Creating your first JSON Schema](https://json-schema.org/learn/getting-started-step-by-step) · EN. Пройди первую схему: type, properties, required, ограничения и вложенные структуры.

**Справочник:**

- [S41 XML 1.0](https://www.w3.org/TR/xml/) · EN. Посмотри синтаксис XML, элементы и атрибуты. Не читай стандарт целиком.

**Сделай:** опиши JSON занятия и записи. Для даты начала используй однозначное представление времени с зоной или смещением и запиши правило интерпретации. Подготовь один корректный и шесть некорректных примеров: неверный тип, неизвестный статус, отсутствующий обязательный идентификатор, отрицательная вместимость, пустое имя, неверная дата. В JSON Schema зафиксируй минимум type, required, enum и ограничения чисел/строк.

Затем представь маленький объект уведомления в XML и объясни, какие сведения передал атрибутами, а какие элементами. Не пытайся доказать, что один формат всегда лучше другого.

**Самопроверка:** является ли JSON протоколом? Можно ли по одному примеру определить обязательность? Чем JSON Schema отличается от OpenAPI? Почему null не стоит трактовать как «не изменять» без явного соглашения? Какое поведение у неизвестного поля?

**Готово, когда:** независимый человек по твоему описанию отличает корректное сообщение от некорректного. Настройка валидатора тоже важна: например, проверка `format` не во всех реализациях включена как обязательное ограничение.
