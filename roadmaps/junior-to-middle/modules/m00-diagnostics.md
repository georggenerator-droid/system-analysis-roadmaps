# M00 Проверь входной уровень

[← Маршрут](../README.md) · [Дальше: M01 →](m01-domain-rules.md)

**Результат:** ты понимаешь, какие пробелы мешают самостоятельной работе. Ориентир — 8 часов с разбором.

Выполни задания без готового решения, затем защити их. Можно пользоваться документацией, если фиксируешь, что проверял. Ментор не оценивает скорость воспроизведения определения.

1. За 20 минут подготовь вопросы к требованию «добавить перенос занятия». Назови риски, которых нет в исходной фразе.
2. Напиши Use Case отмены с альтернативами и критериями на границе времени.
3. По таблицам clients/sessions/bookings найди занятия без активных записей и число уникальных клиентов за период. Объясни кардинальность JOIN.
4. Опиши POST создания записи: поля, ошибки, источник владельца, повторный запрос.
5. Нарисуй sequence, где backend сохранил результат, но клиент не получил ответ.
6. Измени поле API и перечисли потребителей, которых нужно проверить.

**Обязательно:**

- [S74 Как мы унифицировали техническое интервью аналитика](https://habr.com/ru/companies/alfa/articles/893846/) · RU. Сравни формат оценки одной команды с тем, что реально проверили задания. Не делай вывод о грейде только по совпадению вопросов.
- [S38 Проектирование спецификации OpenAPI](https://habr.com/ru/companies/ozontech/articles/825008/) · RU. Используй статью как опору для ревью своего API, а не как готовую шпаргалку.

**Правило маршрутизации:** если SQL JOIN, сценарии, HTTP или модели данных пока не получаются, вернись к J05, J07–J13 первого гида. Если базовая работа стабильна, переходи к M01. Для разработчика можно сократить знакомые технические блоки после защиты, но не пропускать требования и коммуникацию автоматически. Для бизнес-аналитика, наоборот, часто потребуется больше времени на данные и интеграции.

**Сдай:** таблицу навыков с доказательством, оценкой 0–3, пробелом и следующим заданием. Запланируй первые две недели, затем пересмотри нагрузку. Не помечай навык как подтверждённый только потому, что прочитал соответствующую статью.
